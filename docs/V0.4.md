# v0.4.0 定稿：可观测、紧凑、非阻塞

仅新增用量持久化、结果压缩、后台 execute。Codex 仍负责判断、派发和最终验收；
MCP 只做确定性工作。保留 Claude Code harness、settings/Skills/Plugins 继承、
现有七个 Tools、fresh 只读 Review、原 session 续跑、项目临时授权和进程内 Scheduler。

## 方案评估与调整

原提案三项合理，但落实时必须补齐四个边界：

1. **不要价格**：不保存、计算或返回 SDK 的价格估计，更不猜替用模型身份。
2. **未知不是零**：每次调用单独记账；缺失数据不能被汇总成看似完整的总量。
3. **后台结果要能验收**：状态查询补充已保存的紧凑结果，而不只返回一句摘要。
4. **不能把进程超时当死亡**：用 OS 锁确认 owner 消失，避免心跳延迟和 PID 重用误伤活任务。

## 用量

已核对锁定的 `claude-agent-sdk==0.2.136` 本地 `ResultMessage` 类型：`usage` 是
可空 dict；`num_turns`、`duration_ms`、`duration_api_ms` 是结果字段。
提取统一 `Usage`：

| 字段 | 来源 |
| --- | --- |
| input_tokens / cache_creation_input_tokens / cache_read_input_tokens / output_tokens | terminal ResultMessage.usage 同名字段 |
| total_input_tokens | 三项 input/cache 均已知时相加，否则 null |
| num_turns / duration_ms / duration_api_ms | terminal ResultMessage 同名属性 |

安全读取可选字段；缺失、布尔、负数或错误类型为 null，不影响任务结果。真实 0 保留。
成功和错误 terminal 均记录；无 terminal 的超时/取消也有调用记录，但用量未知。
`total_cost_usd`、`cost_usd` 和模型价格表都不进入新统计。

每次进入 Scheduler 执行槽后、调用 Runner 前插入一条 invocation，记录唯一 ID、
job、operation（execute/continue/review）、stage、session、owner、起止时间、状态和
Usage。排队不算 SDK 调用；`calls` 是 Runner 调用尝试次数，不是底层 HTTP 请求数。
continue 永不覆盖旧 invocation；各次 review 也分别记录。

`get_job_status.usage` 只返回 execution/review/total 三组紧凑总览：计数、
reported_calls、各数值及 complete，不默认返回 invocation 明细。
每个字段只有在该组所有调用都有此值时才求和；有缺失则 null。无历史记录为
calls=0、用量=null，不能理解为旧版本任务没有消耗。

根据 [SDK 官方统计说明](https://code.claude.com/docs/en/agent-sdk/cost-tracking)，本项目
使用单条字符串 prompt 的 `query()`，每次结果对应本次调用；不把恢复会话的前次结果
重复加入本次统计，也不混加逐步消息。`usage` 的范围是 SDK 主循环报告，**不保证包含
CC 内部子 Agent 用量**；因此总览明确标记 `scope=sdk_reported_main_loop`。
替用 provider 的统计仍是报告值，不是本项目独立核算值。MCP 无可信 Codex 会话用量入口，
不会伪造 Codex token 统计，也不会读取其全局聊天记录来拼账。

## 结果压缩

SDK structured-output schema 和 MCP 返回模型双重约束；Runner 结果入库前也裁剪。
fallback JSON、异常路径、continue、review、run_job/run_jobs 子结果、历史状态查询同样受限。

| 字段 | 数量上限 | 单条字符上限 |
| --- | ---: | ---: |
| summary | 1 | 3000 |
| files_changed | 100 | 1024 |
| validation | 20 | 500 |
| evidence | 30 | 800 |
| unmet_criteria | 100 | 1000 |
| error.message | 1 | 2000 |

error.details 另限深度、每层条数和字符串长度；解析失败不返回原始输出。
所有长度按 Unicode 字符，不按字节；数组保持 Worker 原顺序，不在 MCP 中加语义排序器。
CC-1/CC-2 提示词要求顺序：阻塞/失败 → 未满足验收 → 关键证据 → 失败验证 →
关键成功验证 → 普通成功。禁止代码、diff、日志、重复测试输出和隐藏推理的大段返回。

新增 `output_truncated` 与 `omitted`；`omitted.validation=12` 表示删去 12 条，
`omitted.summary_chars=50` 表示删去 50 字符。重复应用不再次累计，短输出的原字段不变。
被裁剪的 Worker 结果不额外保存完整转录；需要细节时去项目或原执行 session 取定点证据。
后台查询 `execution_result` / `review_result` 包含同样受限的结果；旧摘要字段为兼容保留。

## 后台执行与进程生命周期

只有 `execute_task` 新增 `background: bool=false`；`run_job`、`run_jobs`、continue、
review 保持同步，无新工具，无隐藏 Review。

```text
参数/权限校验 → SQLite 创建 QUEUED job + 预分配 session
                 ├─ 立即返回 QUEUED（不是成功）
                 └─ 受管理 asyncio task → 原 Scheduler → EXECUTING
                                                → 原结果状态 + 紧凑结果入库
Codex → get_job_status → 验证完成状态 → 决定 fresh review → 最终验收
```

- 同步与后台共用参数校验、执行实现、限流和状态机；每次仍须绑定 cwd/project_root。
- 提交阶段也受管理并屏蔽请求取消，防止数据库已提交却没有 Worker；后台不继承请求的
  cancellation context。AppState 持有 task 引用，完成回调清理并取出异常。
- 调用开始前排队不消耗执行 timeout；进入槽后沿用原 SDK timeout。
- 普通失败、BLOCKED、timeout 和取消映射原状态；异常不冒充完成。
- FastMCP lifespan 在同一事件循环创建/关闭 AppState；正常关闭先取消并等待后台，
  标记残留 active job 为对应 INCOMPLETE，再关闭数据库并释放 owner。
- owner 是随机 UUID 对应的进程期文件锁（Windows 字节锁 / POSIX flock），与 job
  创建/claim 同事务保存。进程退出 OS 自动释放锁；不依赖 PID 或超时推断死亡。
- 启动与状态查询对 **已确认锁释放** 的旧 owner 原子恢复 QUEUED/EXECUTING/
  RESUMING_EXECUTION/REVIEWING；保留 session 与确认标记，并终结未完 invocation。
- 活 owner 不动。旧版无 owner 的 active job 或锁文件缺失时不能证明死亡，不强制抢占；
  升级前应让 v0.3 任务完成并关闭旧 MCP。遗留不明任务需先确认旧执行进程结束，再人工恢复，
  不盲目提交重复写任务。
- 锁文件不在运行中删除，避免锁路径被重建导致误判；数据库及 `.owners` 目录应保留在
  同一台机器的本地文件系统。跨机器共享状态不受支持。
- Windows 强杀后 WAL 映射短暂未释放时，仅对已复现的初始化 `SQLITE_IOERR_TRUNCATE`
  做有限重连；不重放任务或任意数据库写入。

**后台不能跨 MCP server 重启存活，也不会自动重启 CC。** confirmed execution session
按原规则 continue；unconfirmed 用新 job_id；review 始终用新只读 session。
Codex 接手修复无效任务的判断不变，后台只是执行方式。
强杀 MCP 后，标记中断不等于回滚文件或保证外部 CLI/工具已被操作系统终止；恢复前仍须
检查工作进程与项目状态，避免和遗留写操作重叠。本版不新增跨进程强杀框架。

## 数据与兼容

SQLite 为增量迁移：jobs 新增 owner_id、execution_result_json、review_result_json；
新增 invocations 表及 job/time 索引。旧任务身份、确认标记、根目录和历史摘要保留。
迁移在 BEGIN IMMEDIATE 中检查/加列；保留 WAL、busy_timeout、原子 claim、唯一 job。
数据库操作被取消时等待 SQLite 工作线程结束后才释放连接锁。

MCP 仍为 `mcp>=1.29,<2.0`；不做 MCP Tasks、daemon/IPC/HTTP、worktree、多角色路由、
自动合并、自动复跑或 GUI。未来标准 Tasks 支持稳定后另行评估。
